- [x] **Runtime support check (2026-11-25, calibrated starting weights):**
  - T31 yoloxn: gate.sh bit-identical on 6 frames: libjzdl (QEMU) == ojzdl mips (QEMU) == ojzdl native == jzdl_ref. **Fully supported.**
  - T31 mnv4n: ojzdl == jzdl_ref, but **libjzdl differs in ~56 % of outputs**. Probes: image 46 and wide 1x1 (cin 288/480) match; **mid-graph type 46 (3x3 s2, 5-bit input) does not**: ~1 code in ~2 % of positions, scattered (not padding). Our reference/ojzdl miss a libjzdl rule for 46 off the image (contradicts the TinyDet note "mid-graph 46 == libjzdl"). On our stack (ojzdl) the model runs as trained; on stock libjzdl it would not.
  - T41: magik 2.0.4 converts both (yoloxn 1.2 MB, mnv4n 1.4 MB; yoloxn ONNX vs float twin 0.007, higher than the usual 5e-5: check). **onna: missing Add** (mkgraphq takes Conv/ConvTranspose/Relu/MaxPool/Concat only): yoloxn 111 Adds (7 residual + 104 clamp), mnv4n 125. Likely also missing in onnaq's engine (unverified): stride-2 depthwise, 3 heads, and for mnv4n dense 3x3 s2 mid-graph (onnaq only has the 3-channel stem form).
- [x] **T31 fixed for all models (PR #43, 2026-11-25):** two causes found by bisecting with prefix models + probes: (1) **libjzdl takes the int16 requant shift (53/73/74) modulo 16**: ref/ojzdl now `& 15`, exporter + QAT cap shift at 15 (`net.MAX_SH`): this was the "mid-training requant" risk for every model; (2) ojzdl's C path for mid-graph type 46 padded with -128 and didn't wrap to int16 (ref was right). Gate now 18/18 for persondet v2, YOLO-N, yoloxn, mnv4n.
